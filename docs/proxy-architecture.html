传输与功能边界
理解“原生透传”的范围

      

        
原生路径保留部分协议内容
JSON 响应保留字段、引用与签名。SSE 保留 data 和具名事件，包括未知事件类型。但解析器和写入器会重建报文，原生策略不保留注释、id 和 retry 等传输元数据。

        
上游请求会经过规范化
Copilot 会处理模型别名、过滤 beta 请求头，并规范化 thinking 与工具选项。自定义 Anthropic 上游会将模型名转为小写、删除 context_management、仅保留 output_config.effort，且不转发入站的 anthropic-beta 请求头。因此，这些路径并非字节级透传。

验证范围与排除项
  • Proxy：src/**/*.ts，排除声明文件、index.ts、migration.ts、paths.ts 和 upstream/interface.ts。
  • 管理面板：按项目声明的非 View 范围统计；UI 包装层及其他既有排除项未作调整。
  • 脚本：scripts/lib/**/*.ts，不含测试文件。
  • 未验证真实端到端调用、真实上游凭据、套接字级取消或已部署服务。

        
新增且通过的契约验证
  • Anthropic ↔ Chat 的文本、用量，以及两轮交互中的工具 ID 和转义 JSON。
  • JSON / SSE 结束原因一致性，以及顺序工具调用的内容块生命周期。
  • 原生 JSON 中的未知字段、引用、签名和提示词缓存元数据。
  • 原生 SSE 中的签名内容与未知事件类型。
  • 两轮 Chat ↔ Responses 交互中的 call_id 完整性。
  • 不支持的路由明确返回 400，且不调用上游。
  • 对 LF / CR 行尾，在每个可能的字节位置分成两片，验证 UTF-8 解析。

        
性能证据与局限
  • R06 用确定性计数验证多余工作：取消后仍转换全部 20 个待处理分片，不依赖计时阈值。
  • 服务端工具拦截走独立路径，绕过常规 Runner；完整缓存响应后再回放 SSE，会推迟首次输出并占用缓存内存。
  • 既有 test/perf/sse.bench.test.ts 测量的是 parseSSELine 和 parseSSEStream，通常一次提供完整缓冲区，没有测量生产路径使用的 events(response) 解析器。
  • 未结束的超长 SSE 行会被反复扫描。这是静态审查发现的风险，尚无延迟或内存实测结果。

        
尚未验证的协议边界
格式错误或被截断的工具参数目前会抛错，回退行为需要明确契约。已检查特定模型的采样限制、特定供应商拆分 id/name 的情况，但未证明其正确性。本次结果不涵盖真实上游或套接字级取消。
