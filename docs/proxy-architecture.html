理解“原生透传”的范围

      

        
原生路径保留部分协议内容
Anthropic 原生 JSON 保留响应字段、引用与签名，SSE 保留 data 和具名事件，包括未知类型。解析器和写入器会重建报文；Anthropic 原生策略不转发注释、id、retry，Chat / Responses 路径则保留其已有的传输字段行为。

        
上游请求会经过规范化
Copilot 会处理模型别名、过滤 beta 请求头，并规范化 thinking 与工具选项。自定义 Anthropic 上游会将模型名转为小写、删除 context_management、仅保留 output_config.effort，且不转发入站的 anthropic-beta 请求头。因此，这些路径并非字节级透传。

现有 UT 能确保翻译正确吗？
UT 能证明已覆盖的契约，不能保证所有供应商与输入都正确。初审在行覆盖率 100% 的模块中仍复现缺陷；当前新增回归约束事件顺序、模型能力、用量、拒答和取消行为，保留未验证范围。

        
验证范围与排除项
  • Proxy：src/**/*.ts，排除声明文件、index.ts、migration.ts、paths.ts 和 upstream/interface.ts。
  • 管理面板：按项目声明的非 View 范围统计；UI 包装层及其他既有排除项未作调整。
  • 脚本：scripts/lib/**/*.ts，不含测试文件。
  • 未验证真实端到端调用、真实上游凭据、套接字级取消或已部署服务。

        
新增且通过的契约验证
  • Anthropic ↔ Chat 的文本、用量，以及两轮交互中的工具 ID 和转义 JSON。
  • JSON / SSE 结束原因一致性，以及顺序工具调用的内容块生命周期。
  • 原生 JSON 中的未知字段、引用、签名和提示词缓存元数据。
  • 原生 SSE 中的签名内容与未知事件类型；流内错误保留原样转发并计入失败。
  • 七种策略的请求 / 响应取消、挂起读取、背压与迟到 dispatch；服务端工具和重试路径也纳入取消验证。
  • 两轮 Chat ↔ Responses 交互中的 call_id 完整性。
  • 不支持的路由明确返回 400，且不调用上游。
  • 对 LF / CR / CRLF 行尾，在每个可能的字节位置分片，并覆盖逐字节、空读取和 UTF-8 边界。

        
性能证据与局限
  • R06 的确定性对照：取消后额外转换从 20 降为 0，提前退出会取消上游读取器；没有测量网络计费或套接字关闭时延。
  • 服务端工具拦截走独立路径，绕过常规 Runner；完整缓存响应后再回放 SSE，会推迟首次输出并占用缓存内存。
  • 既有 test/perf/sse.bench.test.ts 测量的是 parseSSELine 和 parseSSEStream，通常一次提供完整缓冲区，没有测量生产路径使用的 events(response) 解析器。
  • R05 改为仅扫描新增分片，并在完整行出现时拼接缓存，消除反复扫描未结束长行的路径；字节分片与长行 UT 通过，未做吞吐或内存基准测量。

        
尚未验证的协议边界
常规 Runner 翻译流缺失 finish_reason 时已验证会报错，不会伪造成功结束。格式错误的工具参数、供应商对 id/name 的特殊拆分及所有模型采样组合仍未穷尽验证。翻译工具参数会缓存到 finish_reason；服务端工具仍会完整缓存响应再回放 SSE，其重组器的异常工具分片与截断行为不在上述 Runner 契约的证明范围内。
